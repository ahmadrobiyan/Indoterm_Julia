## 4. The trap that shaped the design — do not undo this

**Every `verify_*` gate prints its verdict and exits 0 even on failure.** Verified for V1
(`verify_walras_gdp` prints `❌ V1 ... FAILS`), V3 (`verify_path_independence` prints
`❌ FAILED`), and V9 (`verify_coalprice_reference` — its `exit(1)` is an early precondition
guard only, not the verdict). `@assert`s in `verify_numeraire`/`verify_homogeneity_tol` guard
preconditions, not conclusions.

So `scripts/run_gates.sh` applies a **dual criterion** to gates marked `marker` in
`test/gates.tsv`: exit 0 **and** a `✅` present **and** no `❌`/`FAILED`/`FAILS`. Semantics were
tested against four stubbed cases — pass, silent-fail, crash, and mute (asserts nothing) — plus
tier exit-status behaviour. All four behave correctly.

This is a **stopgap**. The real fix is converting those scripts to throwing `Test.jl` `@testset`s.
Until then a green `full` tier means *"no gate printed a failure"*, which is weaker than
*"every gate asserted a pass."* Documented in README under "Known gap: gate verdict contracts".

The same reasoning drove three guards in `test/sensitivity.jl`: `build_model!` reads the six
elasticity keys with a `haskey` fallback to hardcoded defaults, so a missing key would make the
sweep vary **nothing** and emit a table of identical numbers that reads as robustness. The gate
therefore hard-errors if a key is absent, if a vector is all-zero (immune to scaling), or if a
perturbation fails to change the vector.
