### 3.2 Choosing the defining rows for S (the trap)
**Constraints in the Julia model are anonymous** (`@constraint(m, [c=1:na, r=1:nr], …)`,
no names), so there is no row → equation-family map. Two ways to get the row set R that pairs
with S:

(a) **Positional.** `build_model_full!` (`src/build_model!.jl:389–~560`) calls the ~146
`E_*!` functions in a fixed order and `all_constraints(m, F, S)` returns them in creation
order per (F, S) type. In the probe, call `build_model!` yourself and then replay the
`E_*!` call sequence copied from `build_model_full!`, recording
`num_constraints(m; count_variable_in_set_constraints=false)` before/after each call. Fragile
(must be kept in sync with `build_model_full!`) but gives exact names. The relevant functions:
`E_xtradmar_na!` (`build_equations.jl:812`), `E_pdelivrd!` (:826), `E_xtrad!` (:864),
`E_xsuppmar!` (:915).

(b) **Structural (recommended first).** Given S columns, restrict `J` to those columns, find a
maximum bipartite matching of S-columns to rows (each substituted variable appears with a
nonzero in its own defining equation, and the defining equations are the rows in which the
substituted variable is the "output"), then check that `D = J[R, S]` under the matched
permutation is nonsingular and block-triangular (Dulmage–Mendelsohn / a simple topological
sort of the S-dependency graph). If the matching is not perfect or D is not triangularisable,
shrink S and report which family dropped out. This needs no equation names at all.

Cross-check (a) against (b) at n=6 once; then use whichever is simpler.

### 3.3 The computation
```
perm rows → [R; rest], cols → [S; C]
D = J[R,S]  B = J[R,C]  A = J[rest,S]  K = J[rest,C]
D⁻¹·B : sparse triangular solve column-wise (D permuted to triangular; use `lu(D)` only if
        triangularisation fails — its fill is what you are trying to avoid)
K̃ = K − A·(D⁻¹·B)         # watch nnz(K̃) vs nnz(K)
F = lu(K̃)                 # default control = AMD, already the best
report: |C|, nnz(K), nnz(K̃), nnz(F.L)+nnz(F.U), fill vs nnz(K̃), time, peak RSS
verify: b = J*ones; x_S,x_C via Schur path; compare with lu(J)\b — max rel err must be ≲1e-10
```
Peak RSS: `Sys.maxrss()` at the end of each n, or `Process.PeakWorkingSet64` via PowerShell
on the julia PID.

## 5. Traps learned today

- Launching Julia with a trailing `&` inside a Bash tool call dies when the call returns
  (0-byte log, no process). Use the tool's `run_in_background: true` with a long timeout, then
  a Monitor on the log. A 10-region build + 12 factorizations took ~13 min; 14 regions will be
  longer and needs ~10 GB — run sizes one at a time if memory is tight.
- `SparseArrays.UMFPACK` in Julia 1.12: `c = U.get_umfpack_control(Float64, Int)`;
  ordering index `U.JL_UMFPACK_ORDERING`; strategy index is **6** (no Julia constant for it);
  `lu(A; control=c)`. `U.JL_UMFPACK_STRATEGY` does not exist.
- `cached_pipeline(nr)` needs `rmap=` for nr ∉ {6, 34}; the probes avoid that by loading 34
  and calling `aggregate_regions!(agg34, region_map(n), n)` directly.
- Files are CRLF in the working tree; `python` edits must detect and preserve the newline
  style or `assert s.count(old)==1` silently fails (bit me on the IO2020 parking edit).
- `logs/` is git-ignored; if a log must survive, transcribe its numbers into the plan/VV doc.
